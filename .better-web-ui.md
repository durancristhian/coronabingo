# Design Context

## Users

Coronabingo is for friends and families of mixed ages who want to play bingo together, often while connected through a video call. The host creates and prepares a room, calls numbers, and manages the pace of the game; players join, follow the called numbers, and mark familiar bingo cards.

## Brand Personality

Playful, warm, simple, inclusive, and social. The interface should feel easy enough for anyone to understand, lively enough to support a game night, and calm enough that the game state stays clear. Product language is conversational neutral Spanish, using informal tú consistently. The owner selected this preference in the 2026-09-27 copy audit. English should sound natural and use the same game terminology.

## Aesthetic Direction

The selected direction is **Playful game table**: a minimal, all-ages visual system with warm cream backgrounds, friendly color blocking, dark structural outlines, tactile offset shadows, and small bingo-ball details. It should feel like gathering around a physical game table without turning childish or compromising the legibility of dense game states.

Preserve component meanings and the interaction model. The application uses Bricolage Grotesque 700 for titles and Atkinson Hyperlegible Next for body and controls. Lucide remains the approved direction for a later functional-icon migration, with Simple Icons reserved for brand logos. Avoid gradients, glass effects, generic dashboard styling, and decoration that obscures game state.

Colors, iconography, border radii, and other fine visual calibration are intentionally follow-up work. Keep them centralized as design tokens or shared component rules so they can be refined without changing every screen.

Header and footer share a warm off-white background (`--cb-shell: #fdfbf7`), lighter than the cream content canvas (`#fff4de`), with dark ink text.

## Design Principles

1. Familiar game pieces first: a card stays recognizably a bingo card, the bolillero remains a 1–90 number board, and player and sound lists preserve their scanning patterns.
2. One visual language: shared components and real product flows should use the same surface, border, spacing, and interaction rules as the kitchen sink.
3. Readable across generations: maintain clear contrast, comfortable touch targets, obvious selected/disabled states, and legible numeric grids.
4. Responsive by composition: reflow groups when space is constrained instead of squeezing the game pieces or shrinking text excessively.
5. Personality with restraint: use a small number of repeatable visual rules in each proposal so the UI feels designed rather than decorated.

## Implementation Defaults

- Next.js Pages Router with React and TypeScript.
- Existing Tailwind setup and project components, extended with shared semantic classes and one global design-system stylesheet.
- Use `next/font` at the application root, with Bricolage Grotesque 700 for titles and Atkinson Hyperlegible Next for body text, controls, and numbers.
- Keep the production application on its existing icons until the approved Lucide and Simple Icons migration is implemented.
- Keep design decisions in shared components and tokens; the temporary kitchen-sink route has completed its purpose and is removed.
