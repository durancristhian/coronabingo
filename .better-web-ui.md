# Design Context

## Users

Coronabingo is for friends and families of mixed ages who want to play bingo together, often while connected through a video call. The host creates and prepares a room, calls numbers, and manages the pace of the game; players join, follow the called numbers, and mark familiar bingo cards.

## Brand Personality

Playful, warm, simple, inclusive, and social. The interface should feel easy enough for anyone to understand, lively enough to support a game night, and calm enough that the game state stays clear. Product language is conversational Argentine Spanish.

## Aesthetic Direction

Preserve the current typography, icon set, component meanings, and interaction model. The redesign study contains three distinct visual directions applied to the same static kitchen-sink content:

1. Warm outline: inspired by time.fyi's strong typographic hierarchy, thin grid lines, small circular junction markers, warm accents, and low-depth surfaces.
2. Refined current: a more disciplined and professional version of the existing Coronabingo UI, with quieter color, consistent borders, spacing, radii, and elevation.
3. Playful game table: an original, minimal direction with friendly color blocking, tactile bingo-ball details, and a light game-night personality that remains suitable for all ages.

The original kitchen sink remains unchanged as the control. All four versions must coexist and be directly comparable. Avoid new font families, new icon libraries, gradients, glass effects, generic dashboard styling, and decoration that obscures game state.

## Design Principles

1. Familiar game pieces first: a card stays recognizably a bingo card, the bolillero remains a 1–90 number board, and player and sound lists preserve their scanning patterns.
2. One anatomy, three voices: visual proposals may change color, border language, depth, spacing, and emphasis, but not the information architecture or implied functionality.
3. Readable across generations: maintain clear contrast, comfortable touch targets, obvious selected/disabled states, and legible numeric grids.
4. Responsive by composition: reflow groups when space is constrained instead of squeezing the game pieces or shrinking text excessively.
5. Personality with restraint: use a small number of repeatable visual rules in each proposal so the UI feels designed rather than decorated.

## Implementation Defaults

- Next.js Pages Router with React and TypeScript.
- Existing Tailwind setup and project components; use scoped CSS for proposal-specific visual overrides.
- Reuse the current font stack and `react-icons/fi` icons already present in the application.
- No new UI, font, or icon dependencies.
- Static, `noindex` kitchen-sink routes with no Firestore reads or writes.
