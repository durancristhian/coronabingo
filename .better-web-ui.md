# Design context

## Users and tone

Coronabingo is for friends and families of mixed ages playing together, often over a video call. The host prepares the room and directs the game; players follow called numbers and mark familiar cards.

The interface is playful, warm, simple, inclusive, and social. Keep game state clear and instructions understandable to first-time players. Use conversational neutral Spanish with informal tú consistently, as approved in the 2026-09-27 copy audit. English should sound natural and follow the same game terminology from [CONTEXT.md](CONTEXT.md).

## Approved visual direction

The selected direction is **Playful game table**: warm cream backgrounds, friendly color blocks, dark outlines, restrained offset shadows, and small bingo-ball details. Preserve the meaning and behavior of cards, the number board, and player/sound lists when changing their appearance.

Use Bricolage Grotesque 700 for headings and Atkinson Hyperlegible Next for body text, controls, and numbers, loaded with `next/font` in `pages/_app.tsx`. Keep tabular numerals enabled globally.

Header and footer share the warm off-white shell color, lighter than the cream content canvas. Current colors, borders, spacing, and shadows live in `public/css/design-system.css`; adjust shared tokens and component rules rather than copying values into individual screens.

## Design principles

- Keep cards recognizable and the 1–90 number board at ten numbers per row, including mobile widths.
- Use shared components and semantic classes consistently across real application flows.
- Preserve readable numeric grids, clear contrast, usable touch targets, and distinct selected, disabled, and read-only states.
- Reflow surrounding groups at narrow widths while preserving the structure of game pieces.
- Keep decoration restrained. Avoid gradients, glass effects, dashboard styling, and redundant indicators that obscure game state.

## Pending choices and review

Lucide is approved as the direction for a later functional-icon migration, with Simple Icons for brand logos. The app still uses its existing icons; migration is separate implementation work. Other visual refinements require task-specific scope.

The temporary kitchen sink has been removed after design approval. For new visual explorations, use a reviewable local comparison and then update the shared system after a choice is approved. Verify the resulting application using [responsive verification](#responsive-verification).

## Responsive verification

Check affected journeys in Spanish and English. Use CSS-pixel viewports of 320×568, 768×1024, 1024×768, and 1280×800 as the base reference. For a narrow change, select the affected sizes; for broad layout changes, cover the full base plus 390×844 and 1440×900.

Check just below and above breakpoints touched by the change, using the [styles](public/css/) and [Tailwind configuration](tailwind.config.js) as the source. For height-sensitive controls or dialogs, add 844×390 and verify that fields and actions remain reachable with the on-screen keyboard open. Resizing alone does not verify a device keyboard.

Check relevant long content and empty/loading/error states, keyboard access, clipping, and unintended horizontal scrolling. Report the executed journey, browser, viewport sizes, and gaps; distinguish browser emulation from actual-device checks.
